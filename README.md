## 作品・NEWSの更新

v8.1の基準は全69作品、ZETA56件、CHACHA21件、TALELYNX0件、アーカイブ4件。公開先の件数は重複を含み、合計を作品総数として扱わない。

- 作品IDは継続使用し、同じ作品を公開先ごとに重複登録しない。
- 公開先の分類とURLの登録有無を分ける。URL未登録のZETA19件の分類を失わない。
- 初公開日・更新日・移植日、公開状態・アーカイブ状態・リンク利用可否を別々に扱う。
- 採用済み紹介文23件と確定タイトルを保護し、除外済み8作品を再収録しない。
- URL・日付・現在の公開状況を推測で補完しない。作品編集だけでNEWSを自動公開しない。

`data/catalogue.js`の先頭には`Generated by scripts/build-catalogue.mjs. Do not edit.`とあるが、この生成スクリプトは現在のリポジトリに含まれていない。旧データからの無条件の再生成は行わない。生成経路の確定までは、承認された更新範囲を作業ブランチ上の現行掲載データに限定し、更新前後のID・本文・分類・URLを照合する。

通常の一覧・検索・詳細は掲載用データから描画される。一方、VELVET NIGHTはHTMLに4枚の固定カードを持ち、カバー画像パスとカタログの一致で作品詳細へ接続する。データへの作品追加だけではカードは増えない。作品追加・タイトル・画像・リンクの変更では、固定カードと各シリーズ本文も確認する。

詳しい変更範囲と検証手順は[作品データ更新手順書](docs/work-data-updates.md)を参照。

### 未確認事項

- `scripts/build-catalogue.mjs`の実体・所在と、生成に使った入力正本。確認済みリポジトリ・該当パス履歴では見つかっていないが、別の保管先まで不存在とは断定しない。
- 採用済み紹介文23件の承認原資料と作品IDの対応台帳。現行タイトル・本文を基準として保持し、未確認の対応を推測で作らない。
- 除外済み8作品の確定ID台帳。既存の除外方針を維持し、旧データから再取り込みしない。

これらは保守上の未確認事項として管理する。文書の採用だけで作品データ変更や再生成を許可するものではない。

## 更新時の基本確認

1. 最新mainから作業ブランチを作り、更新前のコミットSHAと対象作品ID・承認内容を記録する。
2. 対象外の作品・画像・文章・CSS・JavaScriptに差分がないことを確認する。
3. 作品IDの一意性、期待する総数・公開先別件数・アーカイブ件数、画像と関連ID、NEWSの独立性を確認する。作品追加・削除を承認した場合は、その承認内容に合わせて期待件数を更新する。
4. 全10ページの内部リンク、検索・フィルター・詳細開閉、スマホメニュー、ENTER/SKIP/再入場を確認する。
5. 320・390・768・1280pxで表示と横はみ出しを確認する。スマートフォンのタップ操作も確認する。
6. GitHub Pages互換のJekyllビルドで必要なファイルと配信除外を確認し、エラー・参照切れ・不要ファイルの混入を調べる。未実施の検証は未確認として記録する。
7. 差分と検証結果を確認し、所有者の公開承認を得てからmainへ反映する。公開後はPagesのデプロイ結果と本番URLを確認する。

## GitHub Pagesによる公開

| 設定 | 現在の構成 |
| --- | --- |
| リポジトリ | `Luno-fantasy/luno-works` |
| Source | Deploy from a branch |
| Branch / Folder | `main` / `/(root)` |
| 公開URL | `https://luno-fantasy.github.io/luno-works/` |
| カスタムドメイン | なし |
| HTTPS強制 | 有効 |
| Jekyll | `url: https://luno-fantasy.github.io` / `baseurl: /luno-works` / `theme: null` |

mainの更新が本番更新につながる。設定を変更せず、作業ブランチの差分確認と承認を経て反映する。ブランチ公開方式でも、GitHub管理の`pages build and deployment`が実行される。現在、リポジトリ内に独自の公開workflowは置いていない。

`_config.yml`の`exclude`は旧JS・旧画像・文書等の配信を防ぐために維持する。`.nojekyll`を追加すると除外処理を迂回するため、追加しない。ページ・アセットはプロジェクトURLの`/luno-works/`配下で動作することを確認する。

認証情報、非公開データ、復元用ZIP・Git bundle、一時検証資料は公開リポジトリに追加しない。Jekyllの配信除外は、公開リポジトリ内のファイルを非公開にする機能ではない。
